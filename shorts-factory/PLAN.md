# 🏭 떡상 쇼핑쇼츠 공장 — 전체 기획서

> 가칭이에요. 이름은 나중에 바꿔도 돼요.
> 이 문서는 **코딩을 몰라도 읽을 수 있게** 썼어요. 위에서부터 차례로 읽으면 돼요.

## 0. 한 줄 요약

**"잘 된 쇼핑쇼츠가 원본을 어떻게 요리했는지 AI가 배우고, 새 원본을 넣으면 그 요리법대로 완성 영상을 만들어 주는 앱"**

### 먼저 솔직한 이야기 하나

"**절대** 성공하는 공식"은 세상에 없어요. 유튜브 알고리즘도 계속 바뀌고, 상품 자체가 인기 없으면 편집을 아무리 잘해도 한계가 있어요.

대신 이 앱은 **"성공 확률을 계속 올려 주는 공식"**을 만들어요.

- 영상 쌍(원본 + 완성본)을 많이 넣을수록 공식이 똑똑해져요.
- 올린 뒤 **실제 조회수**를 다시 알려 주면, 잘 된 방법은 더 쓰고 안 된 방법은 덜 써요.

👉 유료 고객에게도 "절대 성공"이 아니라 **"데이터로 검증된 공식"**이라고 말해야 해요. "절대 성공"이라고 광고하면 **과장광고(표시광고법)** 문제가 생길 수 있어요.

## 1. 비유로 이해하기 — 요리사와 레시피 노트

| 요리 | 우리 앱 |
|---|---|
| 🥕 재료 (손질 안 한 채소) | **원본 영상** (타오바오·알리·제조사 영상 등) |
| 🍲 맛집 요리 (손님이 많이 온 음식) | **조회수 높은 완성 쇼츠** |
| 🕵️ 맛집 요리를 먹어 보고 요리법을 알아내기 | **① 학습 모드**: 원본과 완성본을 비교 분석 |
| 📒 레시피 노트 (먹어 볼수록 두꺼워짐) | **성공 공식** (쌍을 넣을수록 고도화) |
| 👨‍🍳 새 재료로 레시피대로 요리하기 | **② 생산 모드**: 새 원본 → 완성 쇼츠 |
| ⭐ 손님 반응 보고 레시피 고치기 | **③ 피드백**: 실제 조회수로 공식 보정 |

앱은 이 **3가지 모드**로 돌아가요.

## 3. 꼭 알아야 할 단어 3개

### 📐 편집 설계도 (전문 용어: EDL, Edit Decision List)
영상 1개를 **어떻게 편집했는지 적은 표**예요. 예를 들면:

| 시간 | 원본에서 가져온 부분 | 자막 | 나레이션 | 효과 | 효과음 |
|---|---|---|---|---|---|
| 0.0~1.2초 | 원본 14.3~15.5초 (물 쏟는 장면) | "이거 모르면 손해" | "잠깐! 아직도 이렇게 닦아요?" | 줌인 120% | 휙 (whoosh) |
| 1.2~2.0초 | 원본 2.0~2.8초 | "3초 컷" | "이거 하나면 끝나요" | 흔들림 | 띵! |
| … | … | … | … | … | … |

- **학습 모드**에서는 AI가 완성본을 보고 이 표를 **거꾸로 알아내요.**
- **생산 모드**에서는 AI가 공식을 보고 이 표를 **새로 써요.** 그러면 편집 프로그램이 이 표대로 영상을 조립해요.

👉 이 앱의 심장은 **"설계도"**예요. AI는 설계도만 쓰고, 영상 조립은 정확한 프로그램이 해요. 그래서 결과가 매번 안정적이에요.

### 📒 성공 공식 (플레이북)
설계도 여러 장을 모아서 뽑아낸 **규칙 모음**이에요.

- 숫자 규칙: "첫 컷은 평균 0.8초", "영상 길이는 25~35초", "자막은 화면 위 60% 지점, 노란 테두리 흰 글씨"
- 글 규칙: "첫 1초에 '문제 상황'을 보여 준다", "가격은 마지막 5초에 공개한다"
- 금지 규칙: "제품 로고만 3초 이상 보여 주면 이탈이 늘었다"
- 상품 종류별로 따로: 주방용품 공식 / 뷰티 공식 / 전자기기 공식…

### 📊 가중치
조회수 **100만** 영상의 설계도는 조회수 **1만** 영상보다 공식에 **더 크게** 반영해요.
그냥 조회수만 보면 채널 크기 때문에 헷갈릴 수 있어서, **"구독자 수 대비 조회수"**도 같이 봐요.

## 4. 학습 모드: AI가 분석하는 항목 체크리스트

원본과 완성본을 **둘 다** Gemini에게 보여 주고, 아래 항목을 **정해진 양식(JSON)**으로 답하게 해요.
정해진 양식으로 받아야 수백 개를 모아서 통계를 낼 수 있어요.

### 4-1. 구조 (대본 뼈대)
- [ ] **훅(첫 1~3초)**: 어떤 장면, 어떤 말, 어떤 자막으로 시작했나? 훅 유형(문제 제기 / 충격 결과 / 질문 / 가격 / 비포애프터)
- [ ] **흐름**: 훅 → 문제 → 해결(시연) → 장점 나열 → 가격·구매 유도 중 어떤 순서인가?
- [ ] **전체 길이**, 각 파트의 길이
- [ ] **CTA(행동 유도)**: "고정댓글 확인", "프로필 링크" 등 언제, 어떻게?
- [ ] **반복 시청 장치**: 끝과 처음이 이어지는 루프 구조인가?

### 4-2. 컷 (자르기)
- [ ] 원본에서 **어떤 부분을 썼고 어떤 부분을 버렸나** (원본 시간 ↔ 완성본 시간 연결)
- [ ] 컷 개수, 평균 컷 길이, 가장 짧은/긴 컷
- [ ] 순서를 바꿨나? (예: 결과 장면을 맨 앞으로)
- [ ] 속도 조절 (빨리감기, 슬로모션)

### 4-3. 화면 틀 (레이아웃)
- [ ] 화면 비율, 원본을 어떻게 세로로 맞췄나 (자르기 / 위아래 흐린 배경 / 위아래 띠)
- [ ] 위쪽 제목 띠, 아래쪽 가격 띠 같은 **고정 틀**이 있나? 색·위치·글자
- [ ] 줌인·줌아웃·흔들림·화면 분할

### 4-4. 자막
- [ ] 자막 위치, 글꼴 느낌, 크기, 색, 테두리, 배경 박스
- [ ] 한 번에 몇 글자, 몇 줄? 단어별로 튀어나오나(팝업)?
- [ ] 강조 단어 색 바꾸기, 이모지 사용
- [ ] 자막 문장 **전체 받아쓰기**

### 4-5. 나레이션·대본
- [ ] 나레이션 있음/없음, 목소리(성별·나이대·톤·속도)
- [ ] 대본 **전체 받아쓰기** + 말투 특징 (반말/존댓말, 유행어, 감탄사)
- [ ] 1초당 글자 수 (말 빠르기)
- [ ] 설득 기법 (손해 회피, 사회적 증거, 가격 앵커링, 한정성…)

### 4-6. 소리
- [ ] 효과음 목록과 위치 (휙, 띵, 뿅, 카메라 셔터, 계산기…) — 어떤 **순간**에 넣었나 (컷 바뀔 때, 가격 나올 때)
- [ ] BGM 분위기·빠르기, 나레이션 뒤에서 소리 크기
- [ ] 원본 소리(ASMR 등)를 살렸나?

### 4-7. 화면 전환·효과
- [ ] 전환 종류 (그냥 컷, 휙 밀기, 번쩍임, 줌 전환)
- [ ] 색 보정 (더 밝게, 더 쨍하게)
- [ ] 스티커, 화살표, 동그라미 표시

### 4-8. 성과 정보 (사람이 입력)
- [ ] 조회수, 좋아요, 댓글, 구독자 수, 올린 날짜, 플랫폼(유튜브/틱톡/릴스), 상품 카테고리
- [ ] (있으면) 평균 시청 지속률, 판매 수

> 💡 **망한 영상도 넣어 주세요!** 잘 된 것만 보면 "원래 누구나 하는 것"과 "진짜 성공 비결"을 구분할 수 없어요.
> 같은 사람이 비슷하게 만들었는데 **잘 된 것 vs 안 된 것**을 비교할 때 공식이 가장 빨리 좋아져요.

## 5. 공식이 똑똑해지는 원리 (고도화)

1. **쌍 1개 넣기** → 설계도 1장 + 분석 리포트가 창고에 저장돼요.
2. **숫자 규칙은 통계로** 계산해요. (AI 말고 계산기로!)
   - 예: "조회수 상위 20% 영상의 첫 컷 평균 = 0.7초, 하위 20% = 1.9초"
   - 이러면 AI가 지어내는 일 없이 **진짜 데이터**가 공식이 돼요.
3. **글 규칙은 AI가 정리**해요.
   - 쌍이 5개 쌓일 때마다 Gemini가 "지금까지의 설계도 + 통계"를 읽고 공식 문서를 다시 써요.
   - 새 공식에는 **근거**가 붙어요: "이 규칙은 영상 12개 중 10개에서 확인됨"
4. **버전 관리**: 공식 v1, v2, v3… 로 저장해요. 새 공식이 더 나쁘면 예전 버전으로 되돌릴 수 있어요.
5. **카테고리별 공식**: 주방·뷰티·전자기기·생활·반려동물… 쌍이 충분히 쌓인 카테고리는 전용 공식을 가져요. 부족하면 "공통 공식"을 써요.
6. **피드백 반영**: 앱으로 만든 영상의 실제 조회수가 들어오면, 그 영상의 설계도도 학습 데이터가 돼요. 쓸수록 **나만의 공식**이 돼요.
7. **실험(A/B)**: 같은 원본으로 훅만 다른 영상 2~3개를 만들어서 어느 쪽이 더 잘 되는지 확인해요.

## 6. 생산 모드: 5단계 상세 & 쓰는 AI

| 단계 | 하는 일 | 쓰는 AI·도구 |
|---|---|---|
| **1. 영상 분석** | 새 원본을 장면별로 쪼개고, 장면마다 "무슨 장면인지 / 매력 점수 / 훅으로 쓸 만한지" 기록. 상품의 핵심 장점 3개 찾기 | **Gemini** (영상 이해) |
| **2. 편집 계획** | 공식 + 장면 목록으로 **설계도 초안** 작성. 어떤 장면을 몇 초, 어떤 순서로 쓸지 | **Gemini** (공식을 참고서로 같이 줌) |
| **3. 대본·나레이션** | 설계도에 맞춰 대본 작성 → 훅 후보 3개 → AI 목소리로 녹음 | 대본: **Gemini** (선택: Claude로 한 번 더 다듬기)<br>목소리: **Gemini TTS** / **타입캐스트** / **ElevenLabs** / **수퍼톤** 중 선택 |
| **4. 대본에 맞춰 편집** | 나레이션 실제 길이에 맞춰 컷 길이 조정. 말하는 단어 타이밍에 자막 붙이기. 컷 바뀔 때 효과음·전환 넣기. BGM 깔기 | 단어 타이밍: **음성 인식 AI** (Whisper 또는 Gemini)<br>조립: **편집 엔진** (코드, AI 아님 → 정확함) |
| **5. 완성** | 1080×1920 MP4 출력 + 제목·설명·해시태그·고정댓글 문구 | 편집 엔진 + **Gemini** (문구) |

### 부족한 장면을 채우는 보조 AI (선택)
원본에 **훅으로 쓸 장면이 없을 때** 등:

| 필요 | 도구 |
|---|---|
| 짧은 AI 영상 컷 (예: 문제 상황 연출) | **Higgsfield** (Seedance·Kling·Veo 등 여러 영상 AI 모음), **Google Veo** |
| 화질 올리기 (흐린 원본) | **Higgsfield 업스케일** |
| 상품 배경 지우기 / 썸네일 | **Higgsfield**, **Gemini 이미지** |
| 효과음 만들기 | **ElevenLabs 효과음**, 무료 효과음 라이브러리 |
| 떡상 가능성 미리 점수 매기기 | **Higgsfield 바이럴 예측** + 우리 공식 점수 |

## 7. "MCP"를 어떻게 쓰나요?

**MCP = AI 비서에게 꽂는 "플러그"**예요. 플러그를 꽂으면 AI 비서(Claude 등)가 다른 프로그램(Higgsfield, 구글 드라이브, 깃허브…)을 직접 쓸 수 있어요.

이 프로젝트에서는 MCP를 **2가지 방식**으로 써요.

1. **만드는 동안 (지금부터)**
   - 제가(Claude) MCP로 **Higgsfield**를 직접 써서 영상 AI를 시험해 보고, 어떤 모델이 쇼핑쇼츠에 좋은지 비교해 드릴 수 있어요.
   - **GitHub** MCP로 코드를 저장하고 관리해요.
2. **완성 후 (프리미엄 기능)**
   - 우리 앱을 **MCP 서버**로도 열어 줘요. 그러면 고객이 Claude나 ChatGPT에 "이 영상 쇼핑쇼츠로 만들어 줘"라고 말만 해도 우리 앱이 돌아가요. 경쟁 앱에 거의 없는 기능이라 **차별화 포인트**가 돼요.

⚠️ 단, **앱 안에서**는 각 AI 회사의 API(프로그램끼리 대화하는 창구)를 **직접** 불러요. 그래야 유료 고객에게 빠르고 안정적으로 서비스할 수 있어요. MCP는 "사람 대신 AI 비서가 쓰는 길", API는 "앱이 직접 쓰는 길"이라고 기억하면 돼요.

## 9. 단계별 로드맵 (하나씩 차근차근)

> 각 단계가 **끝나면 바로 쓸 수 있는 것**이 생기게 나눴어요. 앞 단계가 잘 돼야 다음 단계로 가요.

### 🔹 0단계. 준비물 모으기 — *아저씨 숙제*
- [ ] **원본 + 떡상 완성본 쌍 10개** 모으기 (목표 30개 이상)
  - 같은 상품이어야 해요. 원본은 보통 타오바오·1688·알리 상품 페이지, 제조사 영상에 있어요.
  - 가능하면 **안 된 영상 쌍도 5개**
  - 폴더 이름 예: `01_실리콘수세미/원본.mp4`, `01_실리콘수세미/완성본.mp4`, `01_실리콘수세미/정보.txt` (조회수·구독자수·올린날짜·링크)
- [ ] Gemini API 키 (이미 있으시면 그대로 사용)
- ✅ **완료 기준**: 쌍 10개 폴더 준비

### 🔹 1단계. 🕵️ 분석기 (학습 모드의 절반) — 약 1~2주
- 원본·완성본·숫자를 올리면 Gemini가 **4장 체크리스트 전체**를 분석해서 보기 좋은 리포트 + 설계도로 보여 줘요.
- 지금의 인스타 앱처럼 **브라우저 + 내 API 키**로 돌아가요. (서버 비용 0원)
- ✅ **완료 기준**: 쌍 10개를 넣어 보고, 아저씨가 봤을 때 "맞아, 이렇게 편집했네" 하고 **80% 이상 맞다**고 느끼면 통과

### 🔹 2단계. 📒 공식 노트 (학습 모드 완성) — 약 1~2주
- 분석 결과가 쌓이고, 통계 + AI 정리로 **성공 공식 v1** 자동 생성
- 공식 버전 기록, 카테고리별 공식, 공식 파일 내보내기/가져오기 (컴퓨터를 바꿔도 유지)
- ✅ **완료 기준**: 쌍 20개 이상으로 공식 v1을 만들고, 아저씨 경험과 비교해서 납득이 가면 통과

### 🔹 3단계. ✍️ 대본 + 🎙 나레이션 — 약 1~2주
- 새 원본을 넣으면: 장면 분석 → 편집 계획표 → 대본(훅 3개 후보) → AI 목소리
- 아직 영상은 안 만들고, **"이대로 편집하세요" 계획표 + 나레이션 음성 파일**을 줘요. 이것만으로도 캡컷에서 편집 시간이 확 줄어요. (**첫 번째로 실제 써먹는 버전**)
- ✅ **완료 기준**: 이 계획표로 직접 만든 영상 5개를 올려 보기

### 🔹 4단계. 🎬 자동 편집 (완성 영상 출력) — 약 3~4주 (제일 어려운 단계)
- 설계도대로 **컷·줌·자막·효과음·BGM·전환**을 넣은 MP4 자동 완성
- 결과 화면에서 자막 고치기, 장면 바꾸기, 훅 바꾸기 → 다시 만들기
- 효과음·BGM은 **상업적으로 써도 되는 것만** 기본 제공
- ✅ **완료 기준**: 원본만 넣고 버튼 1번 → 5분 안에 올릴 수 있는 수준의 영상

### 🔹 5단계. 🔁 피드백 루프 — 약 1~2주
- 만든 영상의 조회수 입력 → 공식 자동 보정
- (선택) 유튜브 채널 연결로 조회수 **자동** 수집
- A/B 실험 기능 (훅만 다른 버전 여러 개)
- ✅ **완료 기준**: 앱으로 만든 영상 30개 이상의 결과가 공식에 반영됨

### 🔹 6단계. 💳 유료 서비스로 만들기 — 약 4~6주
- 회원가입/로그인, 결제·구독, 사용량(크레딧) 관리
- 고객은 API 키 없이 쓰도록 **우리 서버가 AI 비용을 대신 내고** 요금에 포함
- 렌더링 서버, 이용약관·개인정보처리방침, 환불 규정
- **베타 테스터 10~20명** 무료 운영 → 피드백 → 정식 출시
- ✅ **완료 기준**: 첫 유료 결제 1건 🎉

### 🔹 7단계. 🚀 확장 (선택)
- MCP 서버 공개 (Claude·ChatGPT에서 바로 사용)
- 쿠팡·알리 상품 링크만 넣으면 원본 영상 자동 수집
- 유튜브·틱톡·릴스 예약 업로드
- 해외판 (기존 인스타 현지화 앱 기술 재활용: 일본어·영어 쇼핑쇼츠)
- **"모두의 공식"**: 고객들이 동의한 데이터로 만든 카테고리별 공식 (고객이 많아질수록 더 강해지는 구조 = 경쟁자가 못 따라오는 무기)

> ⏱ 기간은 제가 코드를 쓰고, 아저씨가 매 단계 테스트해 주는 속도 기준의 **대략적인 예상**이에요.

## 10. 유료화 기획

### 10-1. 누가 돈을 낼까? (고객)
- 쿠팡파트너스·네이버 쇼핑커넥트·알리 어필리에이트로 **쇼핑쇼츠 부업**하는 분들 (가장 큰 시장)
- 스마트스토어·쿠팡 **셀러** (내 상품 홍보 영상)
- 쇼츠 대행사, 마케팅 대행사

### 10-2. 요금제 예시 (나중에 원가 보고 확정)

| 요금제 | 가격(예시) | 포함 |
|---|---|---|
| 무료 체험 | 0원 | 영상 3개, 워터마크, 공통 공식 |
| 베이직 | 월 2~3만 원대 | 영상 30개/월, 공통 공식 + 카테고리 공식 |
| 프로 | 월 5~9만 원대 | 영상 100개/월, **나만의 공식 학습**, A/B 실험, 고급 목소리 |
| 에이전시 | 문의 | 팀 계정, 채널 여러 개, MCP·API 연결 |

- 영상 1개 만드는 **AI 원가**를 먼저 재 봐야 해요 (분석 + 대본 + 목소리 + 렌더링). 3~4단계에서 실제로 측정해서 **원가의 3~5배** 이상으로 가격을 정하는 걸 추천해요.
- AI 영상 생성(Higgsfield 등)은 비싸서 **추가 크레딧**으로 따로 파는 게 안전해요.

### 10-3. 경쟁 앱과 다른 점
Vrew, 캡컷 자동편집, Opus Clip 같은 앱은 **"일반 영상 자동 편집"**이에요. 우리는:
1. **쇼핑쇼츠 전용** (훅·가격공개·구매유도 구조에 특화)
2. **실제 떡상 데이터로 학습한 공식** + 쓸수록 **나만의 공식**이 됨
3. 편집 이유를 설명해 줌 ("이 훅을 고른 이유: 비슷한 주방용품 영상 14개 중 11개가…")
4. 제휴 링크 문구·고정댓글·광고 표시 문구까지 한 번에

## 11. 조심해야 할 것 (계정·사업 보호)

| 위험 | 내용 | 대응 |
|---|---|---|
| **저작권** | 남의 원본·완성 영상은 저작물이에요. | 학습 모드의 분석은 "편집 방법을 배우는 용도"로 쓰고, **남의 완성본을 그대로 다시 만들지** 않아요. 원본은 판매자·제조사 제공 영상이나 허락받은 영상을 쓰도록 안내해요. |
| **유튜브 수익화** | 남의 영상을 거의 그대로 올리면 "재사용 콘텐츠"로 수익 창출이 거절될 수 있어요. | 나레이션·대본·편집을 **새로** 만드는 게 이 앱의 핵심이라 유리해요. 그래도 원본 비율이 너무 높지 않게 공식에 규칙으로 넣어요. |
| **광고 표시** | 제휴 링크가 있으면 "쿠팡 파트너스 활동의 일환으로 수수료를 받을 수 있음" 같은 **광고 표시가 의무**예요 (공정위 지침). | 설명·고정댓글 문구에 **자동으로** 넣어요. |
| **AI 표시** | 유튜브는 사실처럼 보이는 AI 영상에 표시를 요구하고, 한국 **AI 기본법**도 AI 생성물 표시를 요구해요. | AI 생성 컷을 쓰면 업로드 안내에 "AI 표시 체크"를 띄워요. 유료화 전에 전문가에게 한 번 확인받아요. |
| **목소리 복제** | 남의 목소리를 허락 없이 복제하면 안 돼요. | 기본 AI 목소리만 제공, 목소리 복제는 **본인 목소리만** |
| **과장 광고** | "절대 성공", "100% 떡상"은 표시광고법 위험 | "데이터로 검증된", "성공 확률을 높이는" 표현 사용 |
| **AI 비용 폭탄** | 버그나 악용으로 AI 요금이 많이 나올 수 있어요. | 구글 결제 **예산 알림**, 회원별 하루 사용 한도 |
| **공식 편식(과적합)** | 쌍이 적으면 우연을 공식으로 착각해요. | 규칙마다 근거 개수 표시, 근거 5개 미만 규칙은 "실험 중" 표시 |
