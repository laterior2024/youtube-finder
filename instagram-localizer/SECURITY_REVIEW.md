# 최종 소스 점검 기록

기준일: 2026-10-08. 기준 소스: GitHub 커밋 2ee93ea10e254ecd6def573f1f759ce819afa8f4 및 v2.7 이관 변경.

## 확인 범위

- 기준 저장소의 현재 추적 파일 91개를 읽어 컴퓨터 고유 절대경로와 대표적인 자격 증명 형태를 점검했습니다.
- 개인 키 파일, Google·GitHub·Supabase 등의 실제 키로 의심되는 검사 대상 문자열은 발견하지 못했습니다. 발견되지 않은 값을 “삭제했다”고 기록하지 않습니다.
- .env.example은 설정 이름과 입력 위치만 기록하며 실제 값은 비어 있습니다.
- .env, .env.*, .vercel, node_modules, dist, release, 개인 미디어·백업 폴더를 Git에서 제외합니다. .env.example만 추적합니다.
- 패키지는 PROJECT_FILES.json의 허용 목록만 복사합니다. 목록 밖에 실제 .env.local이나 개인 파일이 있어도 패키지에 넣지 않습니다.
- npm run audit는 파일 누락·잘못된 경로·대표적 키 형태·값이 들어간 .env.example을 검사하고 발견 값은 출력하지 않습니다.
- 테스트의 명시적인 가짜 인증 문자열과 유해 URL 검사 표본은 실제 자격 증명이 아닙니다.
- 실제 비밀번호·API 키를 환경 변수 예시에 채우거나 시험용 GitHub Secrets로 복사하지 않습니다.

## 범위의 한계

현재 PC의 파일 접근 도구가 시작되지 않아 GitHub에 없는 로컬 파일, 브라우저 저장소, 운영 서비스의 비공개 설정값은 직접 열람·검사하지 못했습니다. Git 과거 전체 이력에 대한 별도 비밀 검사도 수행하지 않았습니다. 패턴 검사는 모든 종류의 비밀값을 찾아낸다는 보장이 아닙니다.

과거에 비밀값을 Git에 올린 사실이 확인되면 현재 파일 삭제만으로 해결되지 않습니다. 해당 서비스에서 키를 폐기·재발급하고 이력 정리 범위를 따로 결정해야 합니다. 실제 키는 이 문서에 적지 않습니다.

## 이관 시 유지할 것

- 기존 Supabase의 RLS·회원 승인·관리자 보호·요청 한도.
- Google·Apify 키는 회원이 직접 앱 설정에 입력하는 방식.
- VITE_ 변수에 비밀값을 넣지 않는 원칙.
- setup.ps1은 기존 .env.local 보존, start.ps1은 자기 PC의 루프백 주소로만 실행.
- PowerShell 스크립트가 컴퓨터 전체 실행 정책·방화벽·계정 권한을 변경하지 않는 구성.
