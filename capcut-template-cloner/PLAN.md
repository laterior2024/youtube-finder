## 1. 왜 만드나

떡상하는 쇼츠·롱폼 채널은 대부분 **매 영상 같은 틀**을 써요.
위아래 검은 박스, 상단 굵은 제목, 노란 테두리 자막, 오른쪽 위 로고… 이 틀이 채널의 "얼굴"이고, 시청자가 스크롤을 멈추는 이유예요.

지금 이 틀을 따라 하려면:
- 스크린샷을 찍고 → 포토샵/스포이드로 색 따고 → 캡컷에서 박스 크기 눈대중으로 맞추고 → 비슷한 폰트 찾고…
- **1개 틀 만드는 데 1~2시간**, 그리고 결과는 어딘가 어색해요.

👉 **이 앱의 약속: URL 넣고 3분 뒤, 캡컷에서 열면 틀이 이미 깔려 있다. 내 색/내 로고로 바꾼 변형도 3~5개.**

## 2. 누가 쓰나

| 사용자 | 원하는 것 |
|---|---|
| 쇼츠 부업러 (정보/썰/랭킹 채널) | 떡상 채널 포맷을 빠르게 내 채널에 적용 |
| 편집 외주자 | 클라이언트가 "이 채널처럼" 할 때 틀을 즉시 세팅 |
| 여러 채널 운영자 | 채널마다 다른 틀이 필요 → 변형 3~5개 |

**핵심 시나리오 (해피 패스)**
1. 떡상 쇼츠 URL 붙여넣기
2. 앱이 분석 → 화면에 원본 프레임 위로 **박스·자막·로고 영역이 색칠되어** 보임 ("이게 틀이에요")
3. 틀린 부분은 드래그로 고침 (예: 자막 박스가 조금 작게 잡힘)
4. 내 로고 올리기, 채널명 입력
5. "변형 4개 만들기" → 카드 5장(원본 틀 + 변형 4) 미리보기
6. 마음에 드는 것 체크 → **캡컷 초안 .zip + 틀 팩 .zip** 다운로드
7. 캡컷 PC에서 열고 영상만 갈아 끼우면 끝

## 3. 기능 목록

### MVP (먼저 만들 것)
- [ ] **입력**: 스크린샷 3~5장 업로드 (가장 정확하고 법적으로 깔끔함) + 유튜브 URL (Gemini로 분석)
- [ ] **틀 분석**: 캔버스 비율, 고정 박스, 제목 텍스트, 자막, 로고, 색 팔레트, 안전 영역
- [ ] **분석 결과 편집기**: 원본 위에 레이어 겹쳐 보기, 드래그로 위치/크기 수정, 색 스포이드
- [ ] **틀 팩 내보내기**: 투명 PNG 오버레이(1080×1920 또는 1920×1080) + `.srt` 샘플 자막 + 스타일 카드(PNG/PDF) + 폰트 다운로드 링크
- [ ] **캡컷 PC 초안 내보내기** (단계 0 검증 통과 시)
- [ ] **변형 3~5개**

### 나중에
- 채널 URL → 떡상 영상 자동 선별 → 채널 공통 틀 추출
- "왜 먹히나" 리포트 (가독성 점수, 첫 1초 시선 흐름, 자막 크기 적정성)
- 내 템플릿 보관함 / 팀 공유
- 프리미어(MOGRT)·다빈치·Vrew 내보내기
- 자막 애니메이션(팝업·타자기 효과) 분석
- 인트로/아웃트로, 전환 효과, BGM 분위기 분석

## 4. 틀 분석 엔진

### 4-1. 뽑아야 할 항목 (= TemplateSpec 필드)

| 항목 | 세부 | 측정 방법 |
|---|---|---|
| 캔버스 | 9:16 / 16:9 / 1:1, 영상이 놓이는 영역(레터박스) | 프레임 크기 + 고정 영역 계산 |
| 고정 박스 | 위치·크기(%, px), 색(HEX), 투명도, 모서리 둥글기, 테두리, 그림자, 그라데이션 | 정적 영역 검출 → 사각형 근사 → 픽셀 색 측정 |
| 제목 텍스트 | 위치, 정렬, 글자 높이(px), 줄 수, 줄간격, 색, 테두리(두께·색), 그림자, 강조색 단어 | OCR 박스 + 픽셀 측정, 폰트는 후보 매칭 |
| 자막 | 위치(세로 %), 최대 너비, 글자 크기, 색, 테두리/배경박스, 한 줄 글자 수, 강조 규칙 | 여러 프레임에서 **변하는 텍스트** 영역 → OCR |
| 로고/워터마크 | 위치(모서리), 크기, 투명도 | 정적 + 비텍스트 영역 |
| 색 팔레트 | 주색·보조색·강조색·텍스트색 (HEX) | 틀 영역만 대상으로 색 군집(k-means) |
| 폰트 | 추정 폰트 이름 + 대체 무료 폰트 | 아래 4-4 참고 |
| 안전 영역 | 쇼츠 UI(좋아요 버튼, 설명란)에 가려지는 곳 회피 여부 | 규칙 체크 |

> 모든 위치·크기는 **캔버스 대비 비율(0~1)**로 저장하고, px은 1080 기준으로 같이 저장해요. 해상도가 달라도 그대로 쓰기 위해서예요.

### 4-2. 입력별 처리 경로

```
[스크린샷 3~5장] ──────────────┐
[영상 파일 업로드] → 프레임 추출 ─┼─► 픽셀 분석(정확한 숫자) ─┐
                               │                          ├─► 합치기 → TemplateSpec
[유튜브 URL] ─► Gemini 영상 이해 ┴─► 의미 분석(무엇이 무엇인지)┘
                  (+ 썸네일 이미지는 YouTube Data API로)
```

- **유튜브 URL**: Gemini API는 **공개 영상 URL을 직접 입력**으로 받을 수 있어요. 영상을 서버로 다운로드하지 않으니 유튜브 약관 문제를 피할 수 있어요.
  단, Gemini는 픽셀 단위 숫자가 부정확하므로 **"대략적인 좌표 + 역할 + 타임스탬프"**만 받아요.
  → 정확도가 필요하면 앱이 "이 시점(0:03, 0:11, 0:25) 스크린샷을 올려 주세요"라고 안내해요.
- **영상 파일 업로드** (본인이 가진 파일): 브라우저에서 `<video>` + canvas로 1초마다 프레임 추출 → 서버 업로드 없이 분석 가능.
- **스크린샷**: 가장 정확. MVP 기본 경로.

### 4-3. "고정 틀" 찾는 알고리즘 (픽셀 분석)

1. 프레임 N장(최소 3장, 장면이 다른 것)을 같은 크기로 맞춤
2. 픽셀마다 **프레임 간 색 차이(분산)** 계산 → 분산이 작은 픽셀 = 고정 영역 마스크
3. 마스크를 덩어리(connected components)로 나누고 → 각각 **사각형/둥근 사각형으로 근사**
4. 덩어리 안 대표색 = 중앙값 색 (그라데이션이면 양 끝 색 2개)
5. 고정 영역 안의 글자 → **고정 텍스트(제목·채널명)**, 매 프레임 바뀌는 글자 → **자막**
6. 고정 + 글자 아님 + 모서리 근처 + 작음 → **로고 후보**
7. Gemini에게 마스크 오버레이 이미지를 보여주고 **역할 이름 붙이기 + 오검출 걸러내기**만 시킴

> 제목이 영상마다 바뀌는 채널(예: 랭킹 쇼츠)은 "위치·스타일은 고정, 글자는 가변"인 **텍스트 슬롯**으로 저장해요.

### 4-4. 글자 크기·폰트·색 측정

- **글자 크기**: OCR 박스 높이가 아니라 **한글 글자의 실제 잉크 높이**를 재서 캡컷 폰트 크기로 환산 (폰트별 환산 계수 표를 미리 만들어 둠).
- **테두리(stroke)**: 글자 가장자리에서 바깥쪽으로 색이 바뀌는 두께를 px로 측정.
- **폰트 추정** (가장 어려운 부분, 현실적으로 설계):
  1. 캡컷에 기본 탑재된 한글 폰트 + 상업용 무료 폰트(Pretendard, 지마켓 산스, 여기어때 잘난체, 배민 도현체, Black Han Sans, 에스코어드림, 나눔스퀘어 등) **30~50개 후보 목록**을 미리 만듦
  2. 추출한 글자를 후보 폰트로 똑같이 렌더링 → 이미지 유사도(SSIM) 비교 → **상위 3개 추천**
  3. Gemini에게 "고딕/명조/손글씨/굵기" 분류를 시켜 후보를 먼저 좁힘
  4. 결과 화면: "가장 비슷함: 지마켓 산스 Bold (유사도 87%)" + 대안 2개
- **색**: 반드시 **픽셀에서 직접** 뽑음. 압축 노이즈 때문에 영역 중앙값을 쓰고, 흰색/검정 근처는 #FFFFFF/#000000으로 스냅.

### 4-5. 사용자 확인 단계 (중요)

자동 분석은 90%까지만 맞아요. 나머지 10%를 **1분 안에 고칠 수 있는 편집기**가 품질을 결정해요.
- 레이어 목록(박스/제목/자막/로고) + 드래그·리사이즈
- 스포이드로 색 다시 찍기
- 폰트 후보 드롭다운
- "원본과 겹쳐 보기" 슬라이더 (원본 ↔ 재현 틀 비교)

## 5. 캡컷 파일 만들기

### 5-1. 현실 체크 ⚠️
- 캡컷 프로젝트(초안) 포맷은 **공식 문서가 없는 비공식 포맷**이에요.
- PC 캡컷은 초안 폴더(`draft_content.json` / `draft_info.json`, `draft_meta_info.json`, 소재 파일)로 저장돼요.
- 최신 버전(JianYing 6+ / 최신 CapCut PC)은 저장 파일을 **암호화**해요. 다만 알려진 바로는 **외부에서 만든 평문 초안은 여전히 열리는 경우가 많고**, 이를 이용하는 오픈소스(pyCapCut, pyJianYingDraft, CapCutAPI 등)가 있어요.
- **모바일 캡컷은 초안 파일을 가져오는 공식 방법이 없어요.** → 모바일은 "틀 팩"으로 대응.
- 캡컷 공식 "템플릿"(앱 안 템플릿 탭)은 크리에이터 계정으로만 올릴 수 있어서 자동 생성 대상이 아니에요.

👉 그래서 **단계 0에서 "우리가 만든 초안이 사용자 캡컷 버전에서 열리는지"부터 검증**하고, 결과에 따라 방향을 정해요.

### 5-2. 내보내기 결과물 2종

**A. 캡컷 PC 초안 (.zip)** — 압축 풀어서 캡컷 초안 폴더에 넣으면 목록에 뜸
- 트랙 구성 (위 → 아래):
  1. 로고 이미지 트랙 (사용자 로고 또는 "LOGO" 자리표시 이미지)
  2. 제목 텍스트 트랙 (스타일 적용된 샘플 문구 "여기에 제목")
  3. 자막 텍스트 트랙 (스타일 적용된 샘플 자막 3줄, 0~3초/3~6초/6~9초)
  4. 고정 박스 트랙 (박스는 **투명 PNG 이미지**로 넣는 게 가장 안정적 — 캡컷 도형 기능은 포맷이 자주 바뀜)
  5. 메인 영상 자리 (회색 자리표시 영상, 레터박스 위치·크기 맞춤)
- 폰트: 캡컷 내장 폰트면 이름 지정, 아니면 폰트 파일 경로 + 설치 안내
- 좌표 변환: TemplateSpec(0~1, 왼쪽 위 기준) → 캡컷(중앙 기준 −1~1 좌표 + scale) 변환 함수 1개로 관리

**B. 틀 팩 (.zip)** — 모바일·PC·다른 편집기 어디서나
- `overlay.png` : 박스+로고 자리만 있는 투명 PNG (캡컷에서 "오버레이"로 올리면 끝)
- `overlay-with-title.png` : 제목까지 포함 버전
- `subtitle-sample.srt` + `subtitle-style.ass` (ASS는 자막 스타일까지 담음)
- `style-card.png` : 색 HEX, 폰트, 크기, 위치를 한 장에 정리한 카드 (캡컷에서 수동 입력할 때 참고)
- `fonts.txt` : 폰트 다운로드 링크 + 라이선스
- `template.json` : TemplateSpec 원본 (나중에 앱에 다시 불러오기용)

### 5-3. 초안 생성 구현 방법
1. 캡컷 PC에서 **기준 프로젝트를 손으로 하나 만든다** (텍스트 1개, 이미지 1개, 영상 1개)
2. 저장된 JSON을 **골든 파일**로 레포에 보관
3. 속성을 하나씩 바꿔 저장 → JSON 차이(diff)를 비교해 필드 의미 파악 (글자 크기, 색, 테두리, 위치…)
4. 골든 파일을 뼈대로, TemplateSpec 값만 채워 넣는 방식으로 생성 (처음부터 만들지 않음 → 깨질 확률 ↓)
5. 캡컷 버전별 골든 파일을 따로 두고, 앱에서 "내 캡컷 버전" 선택
6. 오픈소스(pyCapCut 등)를 참고하되, 라이선스 확인 후 사용

## 6. 변형 엔진

목표: **"먹히는 이유"는 유지하고, 겉모습은 확실히 다르게.**

### 6-1. 유지할 것 (불변 규칙)
- 정보 위계: 제목이 가장 크고, 자막이 그다음
- 대비: 글자-배경 명도 대비 (WCAG 대비율 4.5 이상)
- 안전 영역: 쇼츠 UI 가림 영역 회피
- 영상이 차지하는 비율 (±10% 이내)

### 6-2. 바꿀 수 있는 축
| 축 | 예시 |
|---|---|
| 색 | 색상환 회전, 보색/유사색 조합, 다크↔라이트 반전, 내 브랜드 색 적용 |
| 박스 모양 | 직각 ↔ 둥근 모서리, 꽉 찬 박스 ↔ 반투명 ↔ 테두리만 |
| 배치 | 제목 위 ↔ 아래, 좌우 반전, 로고 모서리 이동 |
| 폰트 | 같은 계열 다른 폰트 (굵은 고딕 → 다른 굵은 고딕 / 둥근 고딕) |
| 자막 | 흰 글자+검정 테두리 ↔ 검정 글자+흰 배경 박스 ↔ 노란 강조 |

### 6-3. 5개 프리셋 (기본)
1. **충실 복제** — 원본 그대로, 로고·채널명만 내 것
2. **컬러 스왑** — 구조 동일, 팔레트만 변경 (내 브랜드 색 또는 보색)
3. **미니멀** — 박스 반투명·얇게, 폰트 한 단계 가볍게
4. **임팩트** — 대비 강하게, 제목 크게, 강조색 1개 추가
5. **반전 레이아웃** — 제목/자막 위치 교체 또는 좌우 반전

변형은 **규칙 코드로 생성**하고(재현 가능, 무료), AI는 각 변형의 이름·설명·추천 용도만 써요.
생성 후 **불변 규칙 자동 검사** → 대비 부족 등 실패하면 자동 보정.

## 7. 채널 분석

1. 채널 URL → YouTube Data API로 최근 영상 50개 (기존 youtube-finder의 검색·필터 코드 재사용)
2. **떡상 점수** = 조회수 ÷ 채널 평균 조회수 (구독자 대비 조회수도 같이 표시)
3. 상위 5~10개 영상을 Gemini URL 분석 → 각 영상의 틀 추출
4. 영상들 사이에 **공통으로 나오는 요소 = 채널 고정 틀**, 떡상 영상에만 있는 요소 = **"떡상 요인 후보"**로 따로 표시
5. 쇼츠/롱폼 틀을 따로 분리

> 비용 관리: 영상 1개 분석마다 Gemini 호출이 들어가므로 "상위 5개만" 기본값, 결과는 영상 ID 기준으로 캐시.

## 9. 기술 구조

기존 레포와 같은 스택을 써서 배포·유지보수를 단순하게 해요.

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Vite + React + TypeScript | 기존 앱들과 동일 |
| 픽셀 분석 | 브라우저 Canvas + Web Worker (필요시 OpenCV.js) | 이미지가 서버로 안 가서 빠르고 저렴 |
| OCR | Gemini (글자 + 박스) / 보조로 Tesseract.js (한글) | |
| 의미 분석 | Gemini API (이미지 + 유튜브 URL 입력) | 기존 앱이 이미 Gemini 사용 |
| 유튜브 메타데이터 | YouTube Data API v3 | 기존 youtube-finder 재사용 |
| 캡컷 초안 생성 | TypeScript 모듈 (골든 파일 + 값 채우기) | 서버 없이 브라우저에서 zip 생성 가능 (JSZip) |
| 서버 | Vercel 함수 (API 키 보호용 프록시만) | 기존 `api/` 구조와 동일 |
| 저장 | 1차: 브라우저 저장 / 2차: 필요시 DB | |

## 10. 로드맵

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| **0. 캡컷 검증 (3~5일)** | 골든 파일 확보, 텍스트/이미지/박스 넣은 초안을 코드로 생성, 사용자 캡컷 PC 버전에서 열기 테스트 | 코드로 만든 초안이 열리고 스타일(색·테두리·위치)이 맞음. **실패 시**: 틀 팩(PNG+스타일카드)을 메인으로 전환 |
| **1. MVP (2~3주)** | 스크린샷 입력, 고정 영역 검출, 색·박스·글자 측정, 편집기, 틀 팩 내보내기 | 샘플 떡상 쇼츠 10개 중 8개에서 "수정 1분 이내"로 틀 재현 |
| **2. 캡컷 내보내기 (1~2주)** | TemplateSpec → 캡컷 초안 zip, 폰트 처리, 여는 방법 안내 | 10개 틀 모두 캡컷에서 열림, 원본과 겹쳐 봐도 어긋남 2% 이내 |
| **3. URL 분석 + 변형 (2주)** | Gemini URL 분석, 스크린샷 요청 가이드, 변형 5종 + 규칙 검사 | URL만으로 초벌 분석 성공, 변형이 모두 대비·안전영역 통과 |
| **4. 채널 분석 (1~2주)** | 채널 영상 수집, 떡상 점수, 공통 틀 추출, 캐시 | 채널 1개 분석 3분 이내, 비용 영상당 기준치 이하 |

## 11. 위험요소와 대응

| 위험 | 가능성 | 대응 |
|---|---|---|
| 캡컷 포맷 변경/암호화로 초안이 안 열림 | 높음 | 단계 0 검증, 버전별 골든 파일, 틀 팩을 항상 같이 제공 |
| 모바일 캡컷 사용자 | 확실 | 틀 팩(투명 PNG 오버레이)으로 대응, 안내 GIF |
| 폰트 추정 오류 | 중간 | 상위 3개 후보 + 사용자 선택, 무료 대체 폰트 제시 |
| Gemini 좌표 부정확 | 높음 | 숫자는 픽셀 분석이 담당, Gemini는 역할만 |
| 유튜브 영상 다운로드 약관 위반 | — | **영상 다운로드(yt-dlp 등) 하지 않음.** Gemini URL 입력 + 사용자 스크린샷/본인 파일만 사용 |
| 움직이는 틀(애니메이션 박스) | 중간 | MVP는 정적 틀만, 애니메이션은 "감지됨" 표시만 |
| AI 비용 증가 | 중간 | 픽셀 분석은 무료(브라우저), Gemini는 역할 분류만, 결과 캐시 |

## 12. 저작권·윤리 가드레일

"떡상 틀 복제"는 **포맷·레이아웃·스타일 규칙**을 참고하는 것이고, 이건 일반적으로 널리 허용되는 벤치마킹이에요. 하지만 선을 넘지 않게 앱이 막아 줘야 해요.

- ❌ **원본 로고·캐릭터·일러스트·고유 그래픽 이미지는 추출·내보내기 안 함** → 항상 "LOGO" 자리표시로 대체
- ❌ 원본 채널명·워터마크 문구는 샘플 텍스트로 쓰지 않음
- ❌ 원본 영상 프레임을 결과 파일에 포함하지 않음 (미리보기 화면에서만 사용)
- ✅ 결과 화면에 "원본과 구분되도록 최소 1가지 이상 변형을 권장해요" 안내, 변형 프리셋 기본 선택
- ✅ 폰트 라이선스(상업용 가능 여부) 표시

## 13. 성공 기준 / 수익화

**성공 기준 (MVP)**
- URL/스크린샷 → 캡컷 파일까지 **5분 이내**
- 사용자가 손으로 고치는 시간 **1분 이내**
- "원본과 겹쳐 보기" 어긋남 **2% 이내**

**수익화 아이디어**
- 무료: 월 3개 틀, 틀 팩만
- 유료: 캡컷 초안 내보내기, 변형 5개, 채널 분석, 템플릿 보관함
- 확장: "이번 주 떡상 틀 TOP 10" 큐레이션 (기존 youtube-finder 검색과 연결)
